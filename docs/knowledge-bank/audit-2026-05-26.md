# Hermes Documentation Audit — 2026-05-26

> Scope: documentation only (markdown across the repo + cross-checks against `src/`, `server-entry.js`, `docker-compose.yml`, `.env.example`, `package.json`, `swarm.yaml`). Verified against the public upstream `outsourc-e/hermes-workspace` and the agent framework `NousResearch/hermes-agent`.
> Method: mechanical link/version checks + a deep content audit (every cited line was re-verified against the file before any edit).

## TL;DR — the root cause

The documentation defects are **not random**. They cluster into three mechanical causes:

1. **An incomplete fork → "zero-fork" brand migration (Claude/OCPlatform → Hermes), applied by find/replace without semantic awareness.** It correctly updated user-facing canonical text but (a) scrambled meta-documents where "Claude" is the *forbidden/legacy* term, (b) skipped some artifacts entirely, and (c) left fork-era paths/volume names behind. Evidence: the naming-contract doc forbade its own canonical names; `release-2.1.0.md` was still 100% "Claude-Workspace/ClaudeAgent"; the Docker docs point at a `claude-data` volume that no longer exists; `docs/swarm/SKILLS.md` still references `~/.ocplatform/...`.

2. **The release process doesn't touch the docs that encode versions.** `package.json` is bumped at release time, but `CHANGELOG.md` (stopped at 2.0.0), `SECURITY.md` (jumped to a speculative v3.x), and `FEATURES-INVENTORY.md` (frozen at 2.0.0) are hand-maintained out-of-band and each drifted to a *different* version. There is no single "version source of truth" check, and releases are cut via ad-hoc `chore(release):` commits (only v2.3.0 has one; no git tags exist).

3. **`docs/swarm/` was written against an older numbered-lane architecture and never migrated when the roster went semantic.** Recent commits (`286472f align swarm runtime with semantic wrappers`, `d528c49 update swarm orchestrator references`) moved `swarm.yaml`/`AGENTS.md`/`agents/` to a 10-worker semantic roster, but the prose docs still describe `swarm1`–`swarm12` and cite a `swarm-specs/SWARM_SPEC.md` that was never committed.

The README itself — the actively-maintained surface — is largely accurate (routes, endpoints, env vars, and security functions all code-checked OK). Defects concentrate in docs that aren't exercised on every dev loop.
